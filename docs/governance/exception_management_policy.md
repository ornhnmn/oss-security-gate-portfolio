# 취약점 예외 관리 정책

| 항목 | 내용 |
|---|---|
| 문서 ID | OSS-POL-003 |
| 버전 | 1.0.0 |
| 작성일 | 2026-11-27 |
| 관련 정책 | OSS-POL-001, OSS-POL-002 |
| 문서 상태 | Draft |

## 1. 목적

즉각적인 취약점 조치가 어려운 상황에서
위험을 제한적으로 수용하기 위한
예외 승인 및 유효성 관리 절차를 정의한다.

## 2. 예외 허용 기준

| 심각도 | 예외 허용 |
|---|---|
| CRITICAL | 불가 |
| HIGH | 조건부 허용 |
| MEDIUM | 조건부 허용 |
| LOW | 기본 허용 정책에 따라 별도 추적 |
| UNKNOWN | 불가 |

예외는 취약점 자체를 제거하는 조치가 아니며
일시적으로 위험을 수용하는 절차이다.

## 3. 예외 신청 조건

다음과 같은 상황에서 예외를 검토할 수 있다.

- 수정 버전이 제공되지 않은 경우
- 업데이트로 인한 서비스 호환성 문제
- 충분한 변경 검증 기간이 필요한 경우
- 즉각적인 조치가 서비스 장애를 유발하는 경우

업무 편의만을 이유로 예외를 승인하지 않는다.

## 4. 필수 검토 및 등록 항목

- 예외 식별자
- 대상 패키지명 및 버전
- 취약점 식별자
- 예외 신청 사유
- 서비스 영향도
- 보완 통제
- 조치 담당자
- 승인 담당자
- 승인일
- 만료일
- 최종 조치 계획

서비스 영향도와 최종 조치 계획은
관리 문서에서 별도로 검토한다.

## 5. 승인 절차

1. 개발자 또는 서비스 담당자가 예외 신청
2. 보안 담당자가 예외 적격성 검토
3. 보완 통제 및 잔여 위험 검토
4. 독립적인 승인 담당자가 승인
5. 승인된 예외를 정책 파일에 등록
6. Security Gate에서 유효성 검증

자기 승인은 허용하지 않는다.

## 6. 유효기간 관리

예외 승인 기간은 최대 30일로 제한한다.

유효성 검증은 Asia/Seoul 시간대를 기준으로 한다.

승인일 이전에는 예외를 적용하지 않으며
만료일에 도달하면 예외를 적용하지 않는다.

자동 연장은 허용하지 않으며
연장이 필요한 경우 재심사를 수행한다.

## 7. 보완 통제

취약점의 특성에 따라 다음 통제를 검토한다.

- 외부 네트워크 접근 제한
- 취약 기능 비활성화
- 접근 권한 최소화
- 입력값 검증 강화
- 로그 및 이상행위 모니터링

보완 통제의 실제 효과는 별도 검증한다.

## 8. 자동화된 예외 검증

Security Gate는 다음 사항을 검증한다.

- 정책상 예외 허용 여부
- 패키지명 및 버전 일치 여부
- 취약점 식별자 일치 여부
- 승인 상태
- 필수 등록 정보의 존재
- 승인자와 담당자의 동일 여부
- 승인일 및 만료일
- 최대 허용기간
- 중복 적용 가능한 예외 존재 여부

유효하지 않은 예외는 정책 평가에서
허용 근거로 사용할 수 없다.

승인자 및 담당자 비교는 현재 문자열 기반이며
실제 사용자 인증 또는 권한 검증은 포함하지 않는다.

## 9. 예외 만료 및 취소

다음 조건에 해당하는 경우 예외를 재검토한다.

- 예외 유효기간 만료
- 신규 공격 가능성 확인
- 보완 통제의 효과 상실
- 서비스 사용 방식 변경
- 취약점 조치 완료
- 심각도 또는 정책 변경

예외 종료 이후에는 SCA 재검사 및
Security Gate 정책 평가를 수행한다.

## 10. 구현 증적

- security/exceptions.yaml
- scripts/exception_manager.py
- scripts/security_gate.py
- tests/test_exception_manager.py

- reports/all_tests_v6.txt

실제 프로젝트의 운영용 예외 목록은 비어 있다.

테스트용 예외는 승인 및 만료 검증을 위한
가상 입력 데이터이며 실제 조직의 승인 기록이 아니다.
