- 분석 방법: SCA 결과, 공개 보안 권고문 및 애플리케이션 소스코드 대조

## 2. CVE-2020-14343

- 패키지: PyYAML 5.3
- CVSS v3.1: 9.8 (Critical)
- 해당 CVE 수정 버전: 5.4
- 취약점 유형: 안전하지 않은 역직렬화

### 소스코드 분석

sample_app.py의 5~13번 줄을 검토한 결과, 외부 입력이 아닌 고정된 YAML 데이터를 yaml.safe_load()로 처리하고 있음을 확인하였다. 취약점의 악용 조건인 full_load() 또는 FullLoader를 이용한 비신뢰 데이터 처리는 확인되지 않았다.

### 위험도 판단 및 대응

현재 코드에서 직접적인 악용 경로는 확인되지 않았으나, 취약 버전이 설치되어 있으며 향후 기능 확장에 따라 위험이 발생할 수 있다. 예외 승인 없이 배포를 차단하고 보안 수정사항이 반영된 버전으로 업데이트할 것을 권고하였다.

## 3. CVE-2018-18074

- 패키지: requests 2.19.1
- CVSS v3.1: 7.5 (High)
- 해당 CVE 수정 버전: 2.20.0
- 취약점 유형: 인증정보 노출

### 소스코드 분석

sample_app.py의 16~20번 줄 및 main() 함수를 검토하였다. Session 객체를 생성하지만 실제 HTTP 요청, 인증정보 전송 및 리다이렉트 처리는 수행하지 않음을 확인하였다.

### 위험도 판단 및 대응

현재 애플리케이션에서는 취약점의 악용 조건이 확인되지 않았다. 그러나 향후 인증 기반 API 통신 기능이 추가될 경우 인증정보 노출 위험이 존재하므로 배포를 차단하고 패키지 업데이트를 권고하였다.

## 4. CVE-2024-35195

- 패키지: requests 2.19.1
- CVSS v3.1: 5.6 (Medium)
- 해당 CVE 수정 버전: 2.32.0
- 취약점 유형: 부적절한 TLS 인증서 검증

### 소스코드 분석

sample_app.py의 17~18번 줄에서 Session 객체의 verify 속성을 True로 설정하고 있음을 확인하였다. 인증서 검증을 비활성화하는 코드 및 실제 HTTPS 요청은 존재하지 않았다.

### 위험도 판단 및 대응

현재 코드에서 취약점의 악용 조건은 확인되지 않았다. 다만 향후 네트워크 기능 추가에 따른 잠재적 위험을 고려하여 배포를 차단하고 보안 수정사항이 반영된 버전으로 업데이트할 것을 권고하였다.
